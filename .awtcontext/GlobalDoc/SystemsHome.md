# 家园、设备与会话进度

> 状态：最小家园贯穿场景已实现；正式建造/生产体系仍待设计。核对日期：2026-11-10。默认游戏不保存进度，持久会话能力与默认体验必须分开管理。

## 玩家体验目标

玩家观察天然力场，理解其对植物和材料的影响，再通过构式或供煤设备复现条件。家园首版用于验证“观察规律 → 收集资源 → 建造设施 → 看到环境回应”，尚不构成完整经营循环。

## 系统边界与当前交付

| 子系统 | 当前规则 | 主要合同 |
|---|---|---|
| 资源建造 | 开采得到物料；4石头+2铜矿建造一个推力发生器，拒绝条件不扣料 | [物品](Items.md)、[设备](Devices.md) |
| 推力设备 | 2×2格非实体设施；最多64台；煤槽64；每煤30个成功环境步，半径16格向右加速度3600格/秒² | [设备](Devices.md) |
| 程序承载 | 设备固定使用 formula/2 `device/force-emitter/3`；玩家应用构式不会替换设备程序 | [构式函数组合](../../Docs/Architecture/FormulaComposition.md) |
| 运行和停机 | 需要驻留空气及完整活动范围；明确显示缺煤、阻塞、域外和容量等待；回收整批退还成本和未用煤 | [设备观测](GameplayObservation.md) |
| 离区冻结 | 设备、实例、场源整体冻结；回来续接已付费周期，不补算域外时间、不重复扣煤 | [区域活动](RegionActivity.md) |
| 力场育圃 | 两个固定花床；空气、支撑、向右1800–5400格/秒²，累计180个成功步成熟；条件失效停长但不回退 | [育圃](ForceGarden.md) |
| 世界意志援助 | 可请求临时场，也可安装保护并启用设备撤销援助；默认随机PseudoLLM可能不行动 | [持久援助](PersistentInterventions.md) |
| 进度保存 | 底层拥有同提交检查点与旧格式读取；默认 Temporary 游戏关闭/R/换场景不保存旧进度 | [检查点](Checkpoints.md)、[保存边界](../../Docs/Architecture/SessionSaveBoundary.md) |
| 日历续接 | world.meta v7保存日历精确刻度及节奏；旧档从春季08:00开始，仍仅显式持久会话保存 | [昼夜与季节](WorldCalendar.md) |

设备的力是加速度，不是风速；不需要启用数值风后端。设备不编码为地形，也不提供角色碰撞。材料进入设备范围会阻止工作，既有材料移动不会因停机而回滚。

## 当前试玩路径

1. F2 展开 `Force garden`，点击 `Create force garden`。这会替换当前世界；至少需要128格模拟窗口。
2. 查看青色晶体和野生花床，F1查看合成力方向。应用晶体构式后，走到家园花床8格以内，用左键朝花床方向施放。
3. 用面板从真实地层开采建造材料和煤。B切换设备布置，左键放置；设备内右键启停、Shift+右键回收。F2可补煤与查看拒绝原因。
4. 观察花床成熟及设备燃料，离开再返回检验周期续接。多个同向场叠加过强也会停止成长。
5. 在家园面板请求援助，再安装保护并启用设备，观察来源撤销与已有成长保留。

普通新世界与育圃默认运行。全局暂停会冻结游戏；建造、供煤、启停、应用构式及新祈祷会被拒绝。显式单步只推进已配置好的领域状态。独立模拟线程中的动作先返回 Queued，必须等待完整提交的终态；界面收到请求不等于设备已经建成。

默认游戏没有 Save world 按钮，退出后重新生成世界。显式 Persistent 会话才显示 Save world / Save and create force garden，并在退出前协商保存；测试证明这种能力，不代表产品默认已经开启。

## 尚未交付与策划决策

| 待定义能力 | 当前边界 / 决策要求 |
|---|---|
| 完整家园建造 | 当前只有一个推力设备，无房间、家具、结构承重或设施网络 |
| 生产链与经济 | 无合成链、设备连线、自动运输；成熟花圃不产出物品，需要先定义收益与资源消耗 |
| 普适种植生态 | 育圃是开发场景中的两个固定花床，无温湿度生长、繁殖或收获规则 |
| 离线生产 | 当前冻结不补算；远处生产需要另行定义时间、容量和结算规则 |
| 默认进度保存 | 底层可用，产品开关关闭；重新开放前需决定存档槽、覆盖/退出交互和失败恢复体验 |
| 大规模存档 | 每次完整复制已保存块，旧代不自动回收；需要容量/清理策略和性能证据 |

这些条目是后续设计议题，不等于已排期任务。

## 依赖与验收切面

- 资源事务依赖库存与动作合同：缺料、满包、过期设备引用、重复请求不能造成部分扣款或重复收益。
- 环境回应依赖 Simulation 的材料、力场和活动窗口；Gameplay拥有设备/育圃规则，Simulation不依赖家园领域。
- 程序寿命依赖构式运行时与场源归属：停止、回收、离区、世界替换均清楚区分取消与冻结。
- 观测和UI只消费完整提交；世界变化、燃料、场源和花床进度必须来自同一版本。
- 持久模式验收需同时覆盖库存、设备、程序、地区生态与世界块，拒绝损坏/跨域不一致的检查点；默认模式则验证不写入玩家进度。

现有验证入口：`Pixel.Devices`、`Pixel.RegionActivity`、`Pixel.ForceGarden`、`Pixel.Checkpoint`、`Pixel.ProcessPersistence`、`Pixel.Persistence`、`Pixel.InterventionCheckpoint`，以及运行时 `--garden-only` / `--garden-aid-only`。详细文档中的历史结果保留原日期，本次整理没有重跑游戏测试。
