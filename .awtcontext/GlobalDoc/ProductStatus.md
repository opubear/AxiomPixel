# 产品现状与待办

状态：项目管理视图。核对日期：2026-11-10；基线包含工作区已有未提交改动。任务完成/验收的权威状态仍在 AWT，本页不复制任务清单或承诺排期。

## 当前能验证的体验

愿景是“观察规律 → 用构式试验 → 采集与建设 → 改变环境 → 形成愿意生活的地方”。当前各环节已有开发切片，但尚未形成带引导、成长奖励与长期保存的完整玩家流程。

| 体验环节 | 已有能力 | 玩家流程缺口 |
| --- | --- | --- |
| 探索与遭遇 | Natural v2、三群落、地形/矿物/有限水体、地区居民与怪物 | 完整探索目标、居民专用动画/生活、生态繁殖未交付 |
| 理解与创造 | 领域观测、知识历史、formula/2、源码编辑器与五套预设、木棍装载后左键施放 | 面向普通玩家的构式学习、解锁与知识界面未交付 |
| 采集与管理 | 14类资源、4096总量库存、原生快捷栏/背包展示、设备资源成本 | 木棍独立构式、F2掉落与走近拾取已交付；通用格子堆叠、装备与资源掉落仍是提案 |
| 环境改造与家园 | 持续场、煤驱动推力设备、力场育圃开花与地区冻结 | 设备品类、生活内容与长期收益循环未交付 |
| 祈祷与自主权 | 离线PseudoLLM、受限提案、保护撤销、来源历史 | 真实模型服务、产品化交互与完整世界意志成长未交付 |
| 积累与回访 | 底层检查点、多域恢复、旧档迁移 | 普通游戏默认临时会话，不跨重启保存 |

## 待决策与依赖

以下顺序是策划/项目管理建议，不是获准开工的新增任务，也没有预设截止日期。确立目标后再在AWT中拆分需求、实现与验收。

| 建议顺序 | 决策或工作 | 依赖与完成判据 |
| --- | --- | --- |
| 先确定下一次试玩目标 | 选一个短闭环：探索—构式—资源—设备—育圃；明确目标用户与可理解的成功反馈 | 使用现有切片组织流程，能说明玩家在做什么、何时完成；不能只靠开发面板解释 |
| 随试玩确定进度策略 | 是否恢复普通游戏持久化，以及保存/重置/失败如何呈现 | 底层检查点已有；仍需产品入口和当期关闭/重置/旧档验收，不沿用历史通过结论 |
| 资源与成长规则 | 在木棍拾取与统一使用接口上评审50格背包、装备及资源掉落的扩展范围 | 现有35展示格与总量库存不是该方案；先冻结事务和兼容规则，再安排实现 |
| 内容与居民 | 决定居民交互/专用美术、怪物奖励、家园收益与探索目标 | 地区身份与休眠已经具备；不能把当前适生率生成当完整生态或NPC生活 |
| 构式学习与知识 | 确定发现、理解、编辑、装载和使用的玩家流程 | formula/2与观测已有；图形编辑、解锁、教程仍须独立设计 |
| 世界意志接入策略 | 是否接真实网络模型；先定义可感知价值、配置与失败体验 | 保留离线兜底与授权/撤销合同；模型联网及真实连通验收需新增工作 |
| 后续环境/表现扩展 | 天气、湿度点火、BGM、繁殖等按玩法需要选择 | 当前气候查询与资源分类提供接点，不代表规则或播放器已经实现 |

持久BehaviorDSL目前暂缓：已有单次DecisionAPI提案与Formula持续执行覆盖现有家园场景。重启条件见 [决策实验](../../Docs/Architecture/BehaviorDecisionExperiment.md)。

## 已知文档与产品差距

- 原生DebugUI是当前设备、育圃、祈祷和构式编辑的主要入口；系统页标注“开发入口”，不将其包装成完整用户流程。
- WorldWill 仍保留 Ready 枚举和旧提示文字，但当前服务流程不再发布“暂停中Ready后恢复提交”；现行合同以服务代码与系统页为准，提示文案修正属于后续代码/UI工作。
- 地区生态记录与活动对象有容量边界，历史验证不覆盖上限规模和长期负载；具体范围见 [群落合同](WorldBiomes.md)。
- ArtRaw本地原件与部分生成资产不由Git完整分发；必须核对安装/恢复脚本及来源记录，见 [内容资源](SystemsPresentation.md)。

## 验收组织

每次交付同时看玩家可观察的结果、失败/取消、暂停/离区/恢复及适用的平台范围。按系统选择CPU、GPU、试玩或存档检查，避免只以“构建通过”判定玩法完成。

当前文档整理仅核对正文、代码证据、任务记录和链接，未运行游戏测试。最新代码测试证据从对应功能任务及其报告读取；新的功能工作必须补自己的验证，不能继承历史任务通过状态。
