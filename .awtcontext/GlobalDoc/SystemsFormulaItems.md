# 构式、资源与背包系统

状态：函数组合、手持木棍施放、资源收集、方块使用及木棍掉落拾取已实现；获取成长、格子库存和通用装备仍未交付。核对日期：2026-11-11；依据当前工作区，包含尚未提交的功能。

## 玩家体验与闭环

玩家用可组合的构式表达“何时、在哪里、发生什么”，通过开采取得真实资源，再把资源用于放土或设备建设。构式与手动操作遵守相同的游戏规则，结果可通过世界变化、库存和回执解释。

当前可玩的链条是：F2掉落木棍 → 走近拾取并选中 → 装载构式 → 左键瞄准施放 → 命中／延时开采 → 资源直接入包 → 使用手持方块或建设设备。构式也可伤害怪物、制造有限寿命力场。配方发现、研究解锁、装备成长尚未形成玩家循环；统一手持使用接口已接入木棍和方块。

## 构式：当前规则

| 分项 | 当前能力 | 约束 |
|---|---|---|
| 描述 | formula/2带类型函数、不可变let、参数封装与action组合 | 定义先于引用，无递归与可变变量 |
| 作用 | dig、wind、bolt、field | 权限、范围、实际资源及地形由Gameplay验证 |
| 组合 | sequence、delay、repeat、on_hit、if_credits、on_wake | 顺序执行；没有并行散射、通用目标选择或随机数 |
| 事件 | 命中后在准确命中位置继续组合，结束后恢复父上下文 | 命中子描述不会因玩家移动漂移 |
| 定位 | World位置或Actor平移绑定，来源与附着对象分开 | 无旋转、运行时重绑定；已经发射/安装的效果保留世界位置 |
| 生命周期 | 成功活动步推进；离区冻结，返回接续；取消清理归属效果 | 已提交的开采等事实不回滚，冻结占用容量 |
| 兼容 | 默认formula/2，保留process/1语义与存档兼容 | 旧cast与树形编辑器已删除 |

构式 credits 是实例效果预算，不是物品数量、魔力成长或设备煤槽。每个成功基础作用通常扣一个credit；玩家开采收益与设备燃料由各自领域另外处理。不能将 `if_credits` 解释成“检查背包”。

准确函数签名、错误回执、存档版本和上限以[formula/2合同](../../Docs/Architecture/FormulaComposition.md)为准；设计动机见[构式系统](../../Docs/GameDesign/FormulaSystem.md)。

## 装载与施放

F2点击 `Drop wooden stick` 并走近拾取，F4打开编辑器，`Equip preset`把程序装入当前手持木棍；`Compile process`／`Apply process`接受新旧源码。编译与装载都不发射，旧运行实例继续使用原程序版本。

普通左键使用当前物品：木棍从人物身体外缘朝鼠标施放，地形遮挡时拒绝；方块在身体外侧相邻的完整格子放置并扣除一份库存，人物处于小数格位置时同样适用。Shift＋左键同样使用手持物，右键开采。UI、元素笔刷和设备布置先解释输入。

| 内置预设 | 用于观察的能力 |
|---|---|
| Mining volley | 命中开采与三次重复 |
| Delayed excavation | 固定命中位置上的延时与顺序开采 |
| Alternating force | 正反方向的有限寿命力场 |
| Beacon pulses | 固定发射点反复产生弹体 |
| Wake launcher | 等待显式唤醒后发射 |

`Stop player formulas`取消主角当前运行的构式及其归属效果，保留装载，之后仍可左键施放；`Clear running`清理全部承载者；未应用的草稿不保存。Actor附着仍有单独调试示例，不能据此声称NPC自动施法或装备系统已交付。

## 资源：产出与消耗

当前有十四类资源：土料、石头、煤、铜矿、铁矿、钨矿、金矿、沙、黏土、砂岩、雪、冰、木材、树叶。苔石并入石头；空气、水、蒸汽和火不产出采矿物品。

手动和玩家构式开采均直接入包；容量不足时保留相应材料。圆形开采按格稳定处理，允许部分成功；已成功的格不因后续满包回滚。天然来源与调试固定夹具的环境开采不奖励玩家，避免凭空收集世界行为产生的物料。

| 操作 | 当前资源规则 |
|---|---|
| 玩家背包 | 初始为空，总量容量4096；资源按ItemId汇总，木棍有独立实例且每根占1 |
| 放置方块 | 持有方块时左键在面前放置并消耗1份；缺料、占用或不就绪时拒绝 |
| 建造推力设备 | 消耗4石头＋2铜矿，预检与扣料作为一次游戏动作 |
| 燃料与回收 | 煤槽转移使用真实资源；回收返还建材和未用煤，满包则整体拒绝 |
| 预留 | 已预留数量仍占容量，不可重复消费或转走 |

完整资源身份、容量和事务规则见[Items](Items.md)，设备运行与家园用途见[Devices](Devices.md)。

## 背包：已交付界面与候选方案

原生UI常驻7个快捷格，Tab展开5行7列展示格。1–7或点击选择快捷格，点击背包资源把它绑定到当前快捷格；快捷格仅引用同一份库存，不额外占有或复制物品。当前有效手持格高亮，左键经HandheldItem接口使用它；木棍按实例引用，方块按资源种类引用。详见[手持物品合同](HandheldItems.md)。

开包不暂停世界；面板内点击被消费，面板外仍可操作世界。Escape先关闭背包。界面展示同一提交的总量、可用量和预留状态；世界替换重置展开与绑定。UI选择状态尚不保存。

[背包装备提案](../../Docs/GameDesign/InventoryAndEquipmentDesign.md)提出的50个实际物品格、其中10个快捷格，是未来替换方案。木棍已具备独立实例、地面掉落和走近拾取；通用资源掉落、拖拽、堆叠上限和装备栏尚未实现，不能把35展示格误写成格子库存已经完成。

## 保存与跨系统依赖

默认游戏为Temporary会话，退出不保留进度。显式Persistent会话可保存真实库存、木棍实例与各自构式、地面掉落、已应用工作台构式、活动/冻结实例及归属效果；恢复不重新激活或重复扣料。UI绑定和未应用草稿不在保存范围。

System/Formula只管理独立语言，Gameplay/FormulaBridge负责世界能力与预算，Gameplay/Items负责资源数量、工具实例和统一使用行为，Gameplay/UI负责展示与命中。Simulation不依赖构式、库存或UI；Input只把玩家意图交给Gameplay。

## 待决策与验收切面

- 构式成长：配方如何发现、获得、保存与分享；操作成本与学习曲线如何支持探索。
- 资源循环：掉落实体如何承接开采与怪物奖励，满包时如何保持守恒，是否保留手动/环境开采差异。
- 装备：首个能力变化应能在小场景验证；基于独立物品实例扩展护甲／饰品规则。
- UI迁移：7＋35展示方案到10＋40持有槽方案必须同步动作、预留、保存、快捷选择和输入规则。

验收应覆盖“装载不发射、施放有明确结果、满包不吞资源、回收不丢料、冻结不补跑、恢复不重扣、UI不穿透”。主要入口为 `Pixel.Formula.Composition`、`Pixel.CompositionBinding`、`Pixel.FormulaPresets`、`Pixel.InventoryGameplay`、`Pixel.InventoryUI`、`Pixel.Input`及对应GPU专项；具体CTest名称以[UnitTest配置](../../UnitTest/CMakeLists.txt)为准。

历史结果与限制见[构式验证](../../Docs/Architecture/FormulaCompositionVerification.md)、[原生背包UI](NativeInventoryUI.md)和[当前施放合同](../../Docs/Architecture/FormulaComposition.md)；任务完成状态不能代替后续玩法验收。
