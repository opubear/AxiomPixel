# 泥土对风向影响不明显：诊断记录

日期：2026-10-05。首次排查只做诊断；用户随后明确泥土已经堆进风区。本次据此复现并修复窄高土堆反馈偏弱的问题，不能再用“泥土不在风区”解释该反馈。仍保留粗网格的有限穿流近似。

## 补充场景与已实施修复

使用1024×1024世界、默认32×16风网格、顶部424行风区、y=512开始的地面。泥土堆从x=512、y=344开始向下接到地面，顶部80行位于风区。分别测试1、4、16、32格宽，推进60个1/60秒步。对照世界保留同样地面与风参数但没有土堆，在x=[448,576)、y=[312,424)的空格比较F1合成方向。

| 初始土堆宽度 | 原面积阻力：最大合成方向差 | 修复后：最大合成方向差 |
|---|---:|---:|
| 1格 | 1.080° | 5.368° |
| 4格 | 3.411° | 10.144° |
| 16格 | 12.437° | 24.101° |
| 32格 | 24.363° | 28.353° |

以上使用默认风参数，包含泥土实际移动，比较的是各自空世界对照，不保证用户任意形状都达到该角度。它证明了伸入风区的窄土堆在旧模型下也可能不明显，与风区高度设置无关。

修复集中在 `WindField`：

1. 阻力从各向同性的面积覆盖率改为横/纵两个方向的投影遮挡。行高与列宽各取占据并集，高而薄的土堆不再按很小的体积比例处理。实际泥土速度继续按面积平均。
2. 压力求解和压力梯度使用与局部阻力一致的面响应权重，避免普通投影不考虑阻力方向而重新引入过强流速。
3. 继续每步重建占据，保留实际运动反馈、无泥土和关闭反馈时的语义；没有修改风常数、网格分辨率、F1色彩或引擎。

另用均匀(20,0)风隔离土堆移动，1格宽土堆在60步后：堆顶迎风点(496,332)的风速从(20.987,-3.136)变为(18.776,-10.446)，向上偏转由约8.5°增至29.1°；侧面迎风点(496,360)的水平风速由15.745降至5.670。RMS散度约7.4e-6。新增CPU回归要求堆顶Y<-8、侧面X<8、合成场角差>0.035弧度、土堆稳定及散度<0.001；该用例对原算法明确失败，修复后通过。

当前仍是方向性多孔阻力近似：最小面响应0.001保持压力系统连通，泥土不是逐像素不透风的硬墙。只统计活动风区内占据，风区四边仍周期相接；恰好位于风区外的地面没有加入边界。F1仍显示包含基础Force的合成方向。这些与窄土堆修复的验收区分记录。

## 初次诊断（修复前的历史证据）

下列数据对应旧面积阻力算法；“当前”“本轮”均指首次诊断时的状态。后续修改不会重写历史测量。

## 已确认的原因

### 1. 当前是面积阻力，压力投影不包含泥土边界

`WindField::CoupleDirt` 将泥土覆盖率用于速度阻尼，最后调用普通 `Project()`。`Project()` 对全部周期网格采用同一泊松方程，没有读取覆盖率、固体面或物体法向速度；压力梯度可以把刚刚降低的速度重新引入泥土区域。它能降低速度、产生一定偏转，但不能约束空气绕开泥土。

隔离实验：1024×1024世界，下半部全为静止泥土；32×16网格，初始风(0,60)，关闭扰动、黏性和背景松弛，仅执行一次1/60秒的CoupleDirt。完全占据单元的纯阻力阶段理论速度为60×exp(-1)=22.0728。投影后，泥土内部(512.5,800.5)速度Y=38.5479，空气(512.5,200.5)速度Y=42.5287，仍然朝下穿过地面。有限次迭代造成二者尚未完全相等；周期泊松投影没有固体边界这一点才是不能保证无穿透的根因。

### 2. 默认求解网格远粗于单个方块

默认32×16网格覆盖1024×424个世界格，每个风单元约32×26.5=848个像素。一个泥土块只贡献约1/848的覆盖率，反馈在面平均、双线性采样和压力投影中进一步分散。扩大风区到整个世界时，每单元覆盖2048个像素。

采用默认风参数，在空世界(480,200)放置不同尺寸泥土，与相同风参数但没有泥土的独立世界同时推进60个1/60秒步，在x=[432,608)、y=[152,264)比较：

| 初始泥土尺寸 | 最大风速差（格/秒） | 最大纯风方向差 | 最大F1合成方向差 |
|---|---:|---:|---:|
| 1×1 | 0.542219 | 0.093425° | 0.124278° |
| 4×4 | 8.14407 | 1.45787° | 1.91638° |
| 16×16 | 45.3538 | 12.154° | 13.3923° |
| 32×32 | 66.9517 | 20.463° | 21.019° |

这些是指定位置、种子、时间和采样区域的结果，不是所有场景的上限。单像素首步最大F1方向差仅0.006827°。RGB8量化后，很多变化不到一个色阶，单格反馈难以肉眼辨认。

### 3. F1显示合成场方向，无法单独观察风速

`BuildForceFieldFrame` 调用 `World::GetFieldVelocity`，实际取值为 `60 * Force + wind`；默认基础Force为(0,1)。泥土只反馈到wind，基础向下项仍为60。色彩将合成向量单位化，因此不能显示速度大小；纯向下速度从60降为5仍是相同方向色。没有单独的纯风向或速度大小视图，也没有材质轮廓叠加来定位障碍。

### 4. 风区边界只检查体积重叠，不检查邻接地面

默认地面从存储行512开始，高度为0～511。风场起始高度600或512均不包含任何地面泥土，CoupleDirt扫描不到泥土；即使高度512处风区恰好贴着地表，地表也不会成为风的边界，求解器继续使用周期边界。

1024×1024默认地面与无泥土世界对照，推进60步，在地面附近x=[432,608)、y=[464,576)比较：

| 风场起始高度 | 最大风速差 | 最大F1合成方向差 |
|---|---:|---:|
| 600 | 0 | 0° |
| 512 | 0 | 0° |
| 500 | 80.8666 | 30.913° |
| 0 | 152.369 | 53.4182° |

因此不能笼统断言反馈完全不执行。高度500/0时本实验可观测到明显数值和方向变化，但仍不具备固体无穿透约束。用户未提供当时的确切高度和泥土形状，不能把某个复现场景直接当作用户现场配置。

## 已排除和此前验收缺口

- `Environment::Tick` 在每个固定步内依次推进风、移动泥土、执行CoupleDirt，反馈调用确实存在。
- 世界发布后回填材料，风归Environment所有；F1每个发布帧重新采样，代码中没有因发布清空风或只使用初始风的路径。
- 运行中的Pixel进程路径为build-runtime/bin/RelWithDebInfo/Pixel，启动时间在本轮之前的ImGui构建之后，不是已发现的旧版本启动问题。没有读取用户进程内部的当前UI数值。
- 之前的静止障碍测试用64×64世界、16×16网格，单格影响比例明显高于实际默认世界；GPU用64×32泥土团，验收只要求数值/颜色有差异，未要求单像素可见绕流或固体内速度受约束。已通过的旧测试不能证明上述能力。

## 修复方向

首先在压力求解中引入固体/流体面边界，让法向空气速度匹配障碍物实际速度；地面恰在风区边界也应成为边界条件，而非周期出口。然后按世界尺度选择风网格分辨率，或引入局部细化；单纯增大阻力不能从粗网格恢复单像素几何。调试面板应分开纯风向、风速大小和合成场，并标识泥土位置，便于验证绕流而非仅减速。

这些会改变当前模型，需在后续实现中加入实际1024尺度、薄墙/地表/孤立块、障碍法向速度、移动障碍和数值稳定测试。本轮没有通过调高常数或夸张颜色掩盖限制。
