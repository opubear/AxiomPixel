# 水、蒸汽与火的元胞运动

2026-10-26。当前实现只描述形态：水下落与铺展，蒸汽上升与散开，火焰上窜、摆动与消退。不模拟压力、氧气、温度、热量、体积分数或化学反应。

## 材料与操作

Water=50、Steam=51、Fire=52 都是 World 材料，与 Air/Dirt 共用一格一个材料的占用、分块、区域版本和存档机制。没有独立效果层、粒子实体或每格生命周期字段。水不阻挡角色但阻挡风；蒸汽与火均不阻挡角色或风，也不能开采为物品。

按 2/3/4 选择水/蒸汽/火，左键在空格中投放半径4格的一团材料；按1回到普通工具。F2 的 Element brush 提供相同选择。B设备工具与元素笔刷互斥。笔刷为原生调试工具，不消耗背包；普通泥土放置仍消耗土料。当前点击投放，不是持续喷射器。

笔刷走 Gameplay 的 SpawnElement 动作：半径上限8，限模拟窗口内已驻留空气，不覆盖固体或其他材料，不覆盖设备，暂停或预算延期时拒绝。Debug/Driver 可以调用，普通 Input 和 WorldWill 会话没有此能力；GameInput在显式选择调试笔刷后通过Debug会话执行。每次成功投放只发布一次提交和一条 ElementsSpawned 汇总事实。

## 固定步规则

随游戏60 Hz固定步运行，与渲染帧率无关。CellularMaterials负责纯材料规则，Environment负责收集、裁决与提交，WorldMap负责写入与区域索引；规则不依赖Gameplay、Render或Formula。

水先下落，遇阻后尝试通过空侧格斜向下落，有上方水格时允许横移；孤立水格在最多4格的连续空走廊内寻找落点，每步仍最多移动一格。保留阻止整列侧移振荡的支撑水规则。稳定水体休眠，编辑唤醒半径4格的规则读者。没有液体密度置换或封闭管道压力规则。

蒸汽每步有四分之一机会暂留，否则优先上升，偶尔斜上漂移；遇顶沿侧面寻找空位。火每步尝试上升，偶尔斜上摆动。对角运动要求相邻通道通畅，不穿过墙角。水平风速超过1格/秒时提供倾斜方向；风域外仍独立运行，不计算反向气动力。

蒸汽每个活动步有1/512的消退概率，火为1/64；概率由整数世界坐标、材料和固定步序号散列得到。这是可复现的形态规则，不是固定寿命保证。水与火四邻接接触时火变回Air，水不被消耗；没有自动蒸发、燃烧蔓延或永久火源。持续火柱可由玩法显式补充Fire格构造。

所有目标要求在步首为空。各源只提交移动或原地消退之一，同目标按源坐标裁决；全部scratch准备完后，材料移动和消退在同一批次提交。空间方向/基础力不随材料搬迁。Steam/Fire即使暂留或堵住，也继续唤醒自身区域，消退完后可恢复休眠。窗口外材料冻结，边界阻止移动，不把缺失块当空气。

随机选择不使用可变PRNG状态，预算延期后的同一步重试得到相同规则结果，不重复消退。输入、完整提交与呈现隔离沿用SimulationCommits合同。

## 呈现与保存

呈现映射Steam到淡蓝白透明纹理，Fire到橙色火纹；仍只读取完整提交的材料快照。Content新增原样复制的05_steam_density.png和03_fire_body.png，来源和SHA-256登记在Content/Art/Elements/SOURCE.json。CPU纯色fallback同步提供新材料。

块载荷仍为14字节/格，块文件布局保持v1，仅扩展注册材料ID；旧档读取不需要迁移。新档包含Steam/Fire时旧程序会拒绝未知材料，不支持旧程序读取。消退无需附加状态，保存的会话时钟决定恢复后的规则序列。动态风仍按现有合同重建，因此不承诺带动态风的保存/加载轨迹与不停机运行完全相同。

## 验证入口

- Pixel.Elements：上升扩散、堵住后消退、风倾斜、墙角、水灭火、静水唤醒、负坐标/跨块、窗口冻结、块保存与无风续算一致。
- Pixel.Liquids：水量、静水、排水、混合目标争用及游泳。
- Pixel.Actions/Input/Simulation：投放权限、一次提交/事实、请求去重、快捷键、暂停及预算延期不提交部分结果。
- Pixel.TerrainAssets：新PNG来源、映射和缓存。
- PixelRuntimeSmoke --terrain-only：包含新材料的真实GPU材质检查。
- PixelRuntimeSmoke --elements-only：连续144步注入水、蒸汽、火，检查动态上传和GPU颜色；PIXEL_ELEMENT_CAPTURE_DIR可导出每24步的PPM。

实际执行结果与覆盖边界记录在AWT任务“水蒸汽火元胞运动模拟”，上述清单本身不代表这些检查已经通过。
