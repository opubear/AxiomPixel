# 风场多尺度模拟方案评估

日期：2026-10-12。状态：四类 CPU 策略首版已实现，GPU LBM 尚未实现；见 [实现与验证](WindStrategiesV1.md)。

AxiomPixel 需要在可接受的运行成本下，让风与普通小方块产生可信的双向作用。推荐优先验证“粗网格整体风场、局部障碍与尾流模型、连续方块运动”的组合；如果一格厚墙体、一格宽缝隙和封闭空间通风成为核心玩法，再增加局部精细求解。整体风的演化与像素障碍的识别应使用不同的空间精度。

本文记录候选方案、选择依据和验证计划。本文后续内容保留原方案研究与原型计划，不能视为所有目标已实现。当前增加程序化、粗 NS＋局部模型、自适应有限体积和 CPU D2Q9 LBM 策略；GPU 后端、连续方块运动、精确移动壁面耦合仍未实现。具体首版能力和限制以实现记录为准。

## 当前问题与实现依据

“没有作用”包含两个独立问题，需要分别验证。

**风对方块的作用。** 粗风场仍可在每个方块位置连续采样，网格尺寸并不直接决定方块能否受到风影响。目前移动逻辑将 `60 * Force + wind` 的每个分量按 ±30 格/秒阈值转换成 -1、0、1，再移动到相邻格。方块没有自身速度与位移余量，因此弱风可能长期无法改变移动结果。提高风场分辨率不会消除这个阈值问题。实现见 [Environment.cpp](../../Pixel/Source/Runtime/Simulation/World/Environment/Environment.cpp)。

**方块对风的作用。** 默认 32×16 风网格覆盖 1024×424 个世界格，每个风单元覆盖约 32×26.5 个游戏格。现有按轴投影遮挡与加权压力修正已改善窄高土堆的反馈，但仍属于允许有限穿流的阻力近似，无法恢复单格附近的精确边界、两侧绕流与缝隙连通关系。实现见 [WindField.h](../../Pixel/Source/Runtime/Simulation/World/Environment/Wind/WindField.h) 和 [WindField.cpp](../../Pixel/Source/Runtime/Simulation/World/Environment/Wind/WindField.cpp)。

F1 当前显示叠加基础方向场后的单位化方向，不显示纯风速大小。风明显减速但合成方向变化很小时，颜色也可能几乎不变。评估新方案时，需要分别观察纯风向、风速、物体轮廓与最终移动，避免把显示限制误判为模拟没有反馈。已有模型和历史修复证据见 [风场接口与模型](WindField.md) 与 [风向反馈诊断](WindDirectionDiagnosis.md)。

## 现有求解器的成本基线

2026-10-12 本机微基准使用 `clang++ -std=c++20 -O2 -Wall -Wextra` 编译当前 `WindField.cpp`。世界为 1024×1024，风区为顶部 424 行；仅修改风网格维度，其余风参数使用默认值。固定步长为 1/60 秒，每个场景预热 10 步，随后连续记录 90 步。计时包含 `WindField::Step` 和 `CoupleDirt`，不包含初始化、方块运动、渲染或 GPU 同步。

静态窄墙位于 `x ∈ [512, 516)`、`y ∈ [100, 424)`，即 4 格宽、324 格高；障碍在测量中不移动。

| 风网格 | 每风单元覆盖的游戏格 | 单步总耗时 p50 | 单步总耗时 p95 | 最终 RMS 散度 |
|--------|------------------------|----------------|----------------|---------------|
| 32×16 | 32×26.5 | 0.50325 ms | 0.54042 ms | 0.00064 |
| 64×32 | 16×13.25 | 1.81987 ms | 1.90842 ms | 0.00329 |
| 128×64 | 8×6.625 | 8.42050 ms | 8.56117 ms | 0.01238 |
| 128×128 | 8×3.3125 | 16.73267 ms | 16.84021 ms | 0.03330 |

同批测量还包含空风区和风区下半部分全部为静态泥土两种场景。32×16 时，两者单步总耗时 p50 分别为 0.54000 ms 和 1.32408 ms；128×128 时分别为 11.69817 ms 和 17.58633 ms。不同场景的耗时不能仅用风网格数量解释，泥土扫描与占据统计也是成本的一部分。

以上数据是单次运行中的样本分位数，不是跨多次独立运行的统计置信区间。压力投影每次固定 80 次迭代，扩散固定 20 次迭代；更细网格的散度误差更大，因此这不是等精度性能对比。高分辨率数据也没有通过该探针证明精度达标。该基线支持“全局加密成本显著增加”的判断，不能作为候选混合方案或其他硬件的性能承诺。

## 候选方案比较

下表的成本与适用性是针对当前工程的设计判断，候选方案之间尚无同场景性能测量。

| 方案 | 主要能力 | 成本与限制 | 建议用途 |
|------|----------|------------|----------|
| 程序化风场与障碍约束 | 连续阵风、局部绕流和可控尾流 | 可按需采样，避免全域高精度求解；复杂障碍之间的流量分配难保证 | 对视觉可信度要求高、对精确通风关系要求较低的场景 |
| 粗 NS 与局部障碍及尾流模型 | 保留整体风的演化，为小物体提供近处反馈 | 需要处理粗场与局部修正的重叠、边界和反馈 | 当前项目优先验证的方案 |
| 自适应网格 NS | 在障碍边界、狭缝与重点区域真正提高分辨率 | 跨分辨率压力与通量耦合复杂；碎片密集时细化范围可能接近全域 | 薄墙、开洞、封闭空间通风成为玩法约束时 |
| GPU 格子玻尔兹曼方法 LBM | 规则网格局部更新，适合并行和像素障碍 | 仍需足够空间分辨率；时间步、稳定性及 CPU/GPU 数据交换需测量 | 全面评估 GPU 风场架构时的替代求解器候选 |

### 程序化风场与局部流动模型

可以用背景风、随时间连续变化的扰动和局部流动模型生成风速。对简单孤立障碍，根据其位置、尺度、形状和来流方向构造迎风减速、两侧偏转和背风尾流，无需为整个世界建立像素级求解网格。

二维可用标量流函数构造速度，并在流函数上调节强度与施加边界约束。Curl Noise 提供了无散程序化流场、障碍边界与涡旋模型结合的研究依据；它并不意味着随意叠加局部速度就能满足全部障碍约束。[Curl Noise 论文](https://www.cs.ubc.ca/~rbridson/docs/bridson-siggraph2007-curlnoise.pdf)

该方案可控制视觉效果与局部响应，但不会自动求出多障碍、狭窄通道之间的正确流量关系。不同模型重叠后仍需检查穿透、异常加速与时间连续性。

### 粗 NS 与局部细节组合

保留 NS 处理整体运动，用局部模型补充小物体附近的气流。局部模型应使用实际像素几何和相对来流，并随物体移动、放置或移除而更新。

粗模拟与细节合成已有可参考的方法。Wavelet Turbulence 从低分辨率模拟中提取信息，再合成缺失的小尺度运动；这种思路适合补充流动细节，但不能独立恢复粗网格丢失的墙体与孔洞连通关系。[Wavelet Turbulence 研究说明](https://www.cs.cornell.edu/~tedkim/WTURB/)

### 自适应网格 NS

在平缓区域使用粗网格，在障碍边界、狭缝和关键涡旋附近加密。自适应流体研究证明了这一路线的可行性，同时也体现出非均匀网格压力求解的复杂度。[自适应网格论文](https://www.cs.cornell.edu/courses/cs667/2005sp/readings/losasso04.pdf)

针对二维像素世界，可以评估分块细化或四叉树组织。细化区域必须与粗场交换通量，并处理跨层压力约束；几个互不关联的小模拟窗口容易在接口处产生不合理的流动。还需限制活跃细网格数量，并明确预算不足时的行为，不能假定自适应在密集碎片场景中仍然很便宜。

### GPU 格子玻尔兹曼方法

LBM 通过格点间的局部更新演化流动，规则数据结构适合 GPU 并行；常见二维形式 D2Q9 在每个格点保存九个分布量。该方法已有复杂运动边界的 GPU 实现参考。[NVIDIA LBM 实现说明](https://developer.nvidia.com/gpugems/gpugems2/part-vi-simulation-and-numerical-algorithms/chapter-47-flow-simulation-complex)

LBM 改变求解方式，不会让粗单元自动识别更小的障碍。选择它需要同时评估格点分辨率、内存、时间步和障碍更新成本。当前方块运动在 CPU 上，若每步必须同步读取 GPU 风场，数据交换和等待可能削弱收益；因此应测量完整交互链路，而非只比较 GPU 内核时间。

## 推荐组合与职责划分

### 粗网格处理整体风

以当前 32×16 或 64×32 为原型候选，负责大范围阵风、主要涡旋和整体障碍反馈。分辨率应随风区尺寸评估，不能将默认 424 行风区的格距直接套用到全世界风区。

可试验降低整体风更新频率，同时保持方块运动更新频率并插值风速，但需要验证快速障碍和脉冲响应。降低频率会减少平均工作量，不会直接降低单次求解峰值；更大时间步也可能改变细节与耦合行为。

### 像素几何处理近处反馈

局部修正使用实际障碍边界、来流方向与相对速度。目标是让小方块附近出现可辨认的减速、偏转和尾流，同时使影响随距离衰减；单个小块不应为了“明显”而改变大片天空的风向。

连续土堆应按暴露边界或局部形状组织，避免每个内部像素重复生成尾流。几何可按脏区更新，但必须覆盖放置、移除和成功移动后的状态。大量孤立碎片仍需设置处理预算，不能假定局部模型数量始终很小。

组合后的风速需要统一检查障碍边界。不同局部模型直接相加，或对速度任意乘遮挡系数，都不能自动保证无散和无穿透。精确边界区域可采用局部求解或其他一致的约束方式。

双向耦合还需明确局部模型与粗场各自负责的尺度：局部扰动反馈到粗场时应避免与原有泥土阻力重复计入。若只在采样时添加局部效果，则需明确它缺少向远处传播的模拟历史。具体反馈规则由原型验证确定。

### 方块保存连续运动状态

为可移动材料保存自身速度和位移余量，使风逐渐改变速度，再将积累位移转换为格子移动。材料的质量、风阻和起动条件可分别控制轻质颗粒与堆积泥土的响应。

例如，在无阻挡且最终横向速度已达到 10 格/秒时，方块可以约每 0.1 秒横移一格，而非持续被 30 格/秒死区过滤。碰撞和堆叠仍需约束移动，不能靠累积位移穿过障碍。

这是对现有运动模型的行为变更。物体速度与位移余量应随材料移动；空间基础方向场仍属于格子位置。当前 `Force` 被当作等效速度方向使用，不能直接将其数值当作物理加速度接入新模型，需先统一量纲与积分规则。

### 通风玩法需要保留精细连通关系

如果玩法要求一格厚墙体挡风、一格宽开口通风，应在相应区域保留像素级空气连通关系。一个粗单元内可能存在互不连通的多个空气区域，仅有占据比例或距离场不足以完整表达它们。

此时增加局部精细网格，并将通量与压力约束反馈到整体风场。小尺度几何是否影响玩法应决定细化需求，不能仅按摄像机是否看见来删除仍有物理影响的区域。当前四边周期边界也需与预期入口、出口、地面边界一起评估。

## 原型推进与验证计划

以下是后续实施建议，不是已通过的验收项。先确定目标硬件与风场预算，再测量完整场景的平均成本、峰值和精度。

1. 建立纯风向、风速与障碍轮廓的对照观察方式，保留当前实现作为基线。
2. 独立验证连续方块运动，确认弱风能积累成移动，且碰撞、堆叠、质量与帧率一致性符合游戏规则。
3. 为孤立块和土堆加入局部障碍及尾流原型，检查近处反馈、距离衰减与大量碎片下的成本。
4. 若薄墙、狭缝或封闭空间案例无法满足玩法，再评估局部精细求解；需要 GPU 架构时将 LBM 纳入同场景比较。

| 场景 | 主要观察内容 |
|------|--------------|
| 单个方块与弱风 | 位移随时间积累；近处气流可测变化；远处扰动衰减 |
| 一格厚墙体 | 墙两侧流速与法向穿透；明确近似方案容许的漏风程度 |
| 一格宽缝隙及开洞封洞 | 空气连通关系与通量变化；无残留遮挡或虚假通道 |
| 封闭空间 | 边界条件一致；没有因粗化或周期连接产生不合理通风 |
| 移动土堆与连续编辑 | 局部响应随几何更新；没有重复阻力、旧尾流源或明显跳变 |
| 密集碎片与大范围地形 | 占据更新、局部采样、压力求解及同步的分项成本和峰值 |

数值观察包括风速与方向差、边界法向速度、通道流量、散度和物体轨迹；比较应固定风区尺寸、初始条件、推进时长及采样位置。性能应同时计入物体更新与必要的数据同步。效果评估还应使用示踪粒子或流线观察时间连续性，不能仅凭 F1 颜色差异验收。

## 工程边界

模型与物体响应仍由 Pixel 的 World 和 Environment 负责；World 不依赖渲染。未来若验证 GPU 求解器，应先设计计算后端与世界交互接口，Pixel 专用求解、shader 和测试保留在 Pixel。相邻 `../Axiom` 继续只读，本地引擎修改仍遵守 `Axiom/AGENTS.md` 和 PixelMain 分支约定。
