# 火把与局部光照

状态为现行首版，核对日期 2026-11-18。画面入口见[呈现系统](SystemsPresentation.md)，物品入口见[手持物品](HandheldItems.md)。

## 火把操作与世界状态

调试角色按 2 持有火把，普通角色按 7。选中有可用数量的火把，玩家位置随帧发布为动态光源。左键瞄准实心地面或其上方的空气格，插下一支点燃的火把。目标和支撑须已驻留，目标须为空且无角色或设备，拒绝时保留背包数量。Shift＋右键点燃或熄灭地上火把，右键回收，满包时保留地上的火把。再次放下时点燃。地上火把锚定于格坐标，挖掉支撑也可继续访问和回收。 [角色初始背包](Items.md#角色初始背包)

库存用 `ItemId::Torch`（1140）保存数量。地上火把使用普通区块中的材料 ID 72（点燃）与 73（熄灭），点灭不改变格子上的力。火把无角色碰撞，仍占一个材料格。显式持久会话的旧存档可以读取，新存档沿用现有区块与 Gameplay v6 格式；新版本写出新增内容 ID 后需要支持这些 ID 的游戏读取。默认临时会话的退出与 R 重置仍遵守原有边界。光照贴图和任务队列从已提交的火把与地形重建。

## 动态传播与分块烘焙

Render 从完整提交读取 64×64 区域及其光学分类。材质版本只负责标记需要重读的区域，遮挡和发光分类实际改变才更新光照依赖。同样不透光的石头和土料可互换而沿用原结果。缺失格视为不透光，重新驻留后参与版本比较。生产呈现使用现有 32 格取样边界覆盖视口外光源和遮挡。

- 手持火把、火和岩浆在活动区域内共享多源泛洪。每个可见区域读取四周 16 格，四邻域按亮度分桶，RGB 各通道取最大贡献。实心方块表面受光并终止传播，水、冰和树叶额外吸收。灯光可沿开口绕行。火和岩浆使用光学网格中的种子，不创建逐格灯对象。
- 持久灯影响半径为 16 格。九个相邻区域的光学版本覆盖每个受光区域的完整输入边界；改墙、点灭、拾取、跨区块加载时，依赖变化的区域丢弃旧结果。可见脏区先用同一批已提交的固定灯做快速泛洪。几何稳定后由一个后台线程逐区烘焙，最多一个任务在途，优先处理靠近视口中心的区域。
- 精细结果按灯到格内样本做 DDA 穿格检测，使用完整方块，封闭的对角墙角阻光。距光源越远贡献越低，多盏固定灯的贡献相加。常规视口每格 2×2 样本，发布面积超过 512×512 格后用每格一个样本。工作线程持有紧凑的区域副本，完成时核对光学依赖与投影采样密度的版本，匹配才替换临时结果。
- 每个区域取当前有效的临时或精细固定光之一，再与动态光相加。移动或移除光源时重建受影响区域的动态场。CPU 缓存限制在当前发布范围，光照帧和工作区计入呈现内存预算。改变结果的区域才更新 GPU 上传版本。

## 合成与边界

后处理对最终场景最近邻采样一次线性 RGB 光照图。图中每 64 个量化级代表 1.0 的光照强度，255 为叠加上限。环境光继续由昼夜季节调节，局部灯光另乘用户调色，然后一起进入 ACES 近似曲线。中间场景的 alpha 保存前景覆盖率，局部光只作用于地形、角色和场景物体。透明前景按覆盖率近似，远景和 UI 保留各自颜色规则。需要局部照明时使用最终呈现 Pass 内的照明 shader，F1 走诊断呈现。

首版使用阴影和距离衰减，天空环境光仍是全局昼夜乘色。宽视口降低采样密度，频繁编辑会保持快速泛洪效果。性能随可见区面积、变化的格子数和精细烘焙的固定灯密度增长。

## 验证入口

```sh
cmake --build build-cpu --target PixelLightingTests PixelCheckpointTests -j4
ctest --test-dir build-cpu -R '^Pixel\.(Lighting|Checkpoint|InventoryUI|ModuleBoundaries)$' --output-on-failure
cmake --build build --target Pixel PixelRuntimeSmoke -j4
(cd Pixel && ../build/tests/PixelRuntimeSmoke --lighting-only)
```

`Pixel.Lighting` 验证薄墙、对角墙角、液体吸收、多灯、跨区域修改、异步结果失效及火把动作。检查点专项保存并恢复已点燃、已熄灭的火把和实际背包库存。GPU 专项用真实呈现链上传光照纹理，将照明 shader 输出逐像素读回，并检查前景覆盖率和 F1。
