# 世界双缓冲验证记录

2026-10-26。基线为开始本次改动时的工作区副本，包含当时尚未提交的 Water/Steam/Fire 元胞实现；没有把这些既有修改计入双缓冲收益。引擎子模块及 `AxiomVersion.json` 未修改。

## 实现边界

`WorldBuffers` 统一管理材料、方向、基础力、风后端和场源。模拟提交后封存当前版本；下一次写入准备另一个槽。读者持有 `shared_ptr<const WorldBuffer>`，不再单独分配材料、Air、Field 快照。Observation 在查询时才生成 API 导出。

正常循环复用两槽。材料载荷共享至首次写入；已有独占载荷按64格脏区域同步。慢读者仍持有旧槽时保留额外版本，不覆盖读者内容；该版本释放后回收。材料与版本元数据纳入流式预算，预算不足保留上一完整提交并允许重试。数值风后端写前克隆，继续沿用原有独立计量合同；本次没有把风/GPU资源并入流式硬预算，也没有实现 GPU 求解或多线程发布。

这不是零拷贝求解器：被修改的材料区域需要同步，现有原地数值风算法需要独立的可写后端。移除的是每个消费者提交时生成的整幅世界/场快照。GPU后端接入时应保持同一个完整版本发布合同，并把读租约保留至GPU fence完成。

## 独立审查

用户指定的独立subagent从工作区改动前副本审查实现，并在修复后重新检查。最终无未关闭的可操作发现。独立运行11项重点测试全部通过，9.34秒；覆盖WorldBuffers、FieldSources、Devices、DeviceRendering、InventoryGameplay、Observation、Simulation、Actions、Chunks、Memory、Persistence。

| 已证实问题 | 修复及复核 |
|---|---|
| 复制只读ForceField门面可生成可写别名 | 禁止ForceField/WindSimulation复制，编译期断言验证 |
| 材料分离因预算失败时，采矿库存可能先增加 | 材料写入预留移到副作用之前；独立复现确认材料与库存均不变 |
| 慢读者累积版本元数据超过预算 | 分配版本前预留；独立复现改为正常延期 |
| 新预算失败可能穿透流式回收或丢失已完成I/O | 取得writer后才消费完成队列，失败恢复外部预留；延期服务保留结果重试 |

数值风配置/Adaptive动态增长的硬预算不属于本次扩展范围：核对改动前合同后保持独立计量，移除了实现中一度引入的不完整限制。审查者未独立测量性能或验证GPU并发。

## Release性能对照

基准入口为 `UnitTest/Benchmarks/PixelWorldBufferBenchmark.cpp`。同一份基准源分别链接改动前、改动后代码，以 `-O3 -DNDEBUG`、1024格物理块构建。构建及其它测试结束后，串行交替执行before/after三轮；每个场景运行72帧，前8帧预热，记录余下64帧的中位数。每个读视图为512×512，包含一次完整模拟提交与F1场图打包，不包含GPU执行。

原始数据见 [三轮CSV](WorldBuffersBenchmark-2026-10-26.csv)。`reserved_bytes` 是World所有权计量口径，包含共享版本去重，不是进程RSS或GPU内存。各场景三轮输出校验值一致；下表为三轮中位数的中位数。

有1–3个读视图的动态风场景，提交阶段从约11.5–29.1ms降至约4.3–5.4ms，整体耗时下降19%–26%。部分采样转移到了实际F1打包阶段，因此不能把提交阶段的下降全部当成整帧收益。只绘制普通材质、关闭风效果、没有查询的消费者不再被提前收取全图场采样成本；这部分未单独计时，不据此推算FPS。

收益有场景边界：空风无读者时增加约2.1µs版本管理成本；程序风无读者时增加约0.155ms（3.7%），主要增加的是保留可写数值后端的成本。运动材料例总耗时下降22.9%，World预留从22.49MiB增至28.66MiB，因为材料载荷双份保留，抵消了部分消费者快照释放的空间。长期异步读者还可能保留更多版本；内存预算与延后提交机制用于控制材料/版本的增长。

后续若无读者场景成为主要热点，应优先考虑让风求解器显式读取前一版本、写下一版本，复用其结果与scratch，而不是先克隆现有原地后端。该改造需要逐个验证MAC/Adaptive/LBM算法的阶段依赖，本次保留数值算法与输出合同。此次测量只代表上述CPU场景，不能外推到GPU计算或所有游戏帧。
